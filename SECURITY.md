# Security Policy

## About Security

Security is important to Rank Flys.

Rank Flys is an EdTech platform designed for students preparing for competitive examinations such as NEET and JEE. We take reasonable steps to protect the application, project, contributors, and users.

If you discover a security vulnerability, please report it responsibly and privately.

## Supported Versions

Security fixes are applied to actively maintained versions of Rank Flys.

| Version        | Supported                     |
| -------------- | ----------------------------- |
| Latest release | Yes                           |
| Older releases | Depends on maintenance status |

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub Issues, Pull Requests, or Discussions.**

If you discover a potential security vulnerability in Rank Flys, please report it privately to the project maintainers.

### Security Contact

**Email:** [flylearning@gmail.com](mailto:flylearning@gmail.com)

Please use this email only for responsible disclosure of security vulnerabilities.

## What to Include

When reporting a security vulnerability, please include as much relevant information as possible:

* A clear description of the vulnerability.
* Steps required to reproduce the issue.
* The affected application or repository component.
* The affected version, if known.
* The potential security impact.
* A proof of concept, if available and safe to provide.
* Any suggested mitigation or fix.
* Relevant screenshots, logs, or technical details where appropriate.

Please do not include real user data or other sensitive information in your report.

## Examples of Security Issues

Examples of issues that should be reported privately include:

* Authentication bypass.
* Unauthorized access to user accounts.
* Authorization vulnerabilities.
* Exposure of private user information.
* Insecure API endpoints.
* Database security vulnerabilities.
* Sensitive information exposure.
* Authentication token leakage.
* API key exposure.
* Remote code execution.
* Injection vulnerabilities.
* Serious application security flaws.

This list is not exhaustive. If you are unsure whether an issue is security-related, please report it privately.

## What Not to Include

Do not include the following information in public GitHub Issues, Pull Requests, or Discussions:

* Passwords.
* API keys.
* Authentication tokens.
* Database credentials.
* Private certificates.
* Signing keys.
* Production secrets.
* Personal information.
* Private user data.
* Confidential business information.

## Responsible Disclosure

Please give the Rank Flys maintainers reasonable time to investigate and address a reported vulnerability before publicly disclosing technical details.

We appreciate responsible disclosure and cooperation from security researchers and contributors.

Please do not access, modify, delete, or expose data belonging to other users while testing a potential vulnerability.

Only test against systems and accounts that you are authorized to test.

## Response Process

After receiving a security report, the maintainers will:

1. Review the report.
2. Assess whether the reported issue is a security vulnerability.
3. Attempt to reproduce the issue when necessary.
4. Assess the potential impact.
5. Work on an appropriate fix or mitigation.
6. Release a fix or update when appropriate.
7. Communicate relevant information to the reporter when possible.

Response times may vary depending on the severity and complexity of the issue.

## Accidental Exposure of Secrets

If a secret is accidentally committed to the repository:

1. Do not rely only on deleting the file.
2. Immediately revoke or rotate the affected credential.
3. Remove the secret from the repository where appropriate.
4. Review repository history if necessary.
5. Check whether the exposed credential was accessed or misused.
6. Replace the credential with a new secure value.

Examples include:

* API keys.
* Passwords.
* Access tokens.
* Database credentials.
* Private keys.
* Signing credentials.

## User Privacy

Rank Flys contributors must not intentionally expose or commit private user information.

If you discover exposed personal or sensitive information, do not reproduce or redistribute it publicly. Report it privately to the maintainers at:

**[flylearning@gmail.com](mailto:flylearning@gmail.com)**

## Security Updates

Security-related updates may be included in project releases and relevant project documentation.

Users should keep their Rank Flys application updated to the latest available version whenever possible.

## Scope

This security policy applies to the Rank Flys source code repository and the project components maintained by the Rank Flys team.

Third-party services, libraries, APIs, or infrastructure may have their own security policies and reporting procedures.

## Thank You

Thank you for helping keep Rank Flys secure.

Responsible security research and vulnerability reporting help us improve the project and protect the Rank Flys community.
